# Visual模态参数配置指南

## 核心参数说明

### 1. VISUAL_USE_DISKANN

**含义**: 选择索引类型

- `true` - **DiskANN索引**（磁盘ANN）
  - 适用场景：**大规模数据**（千万级+帧数）
  - 优势：支持TB级向量数据，内存占用低（70-90%降低）
  - 劣势：首次构建慢，需要额外磁盘空间（1.5-2倍）
  - 性能：略慢于HNSW（~10-20%），但可扩展性强

- `false` - **HNSW索引**（内存ANN）
  - 适用场景：**中等规模数据**（百万级帧数）
  - 优势：查询速度最快，构建速度快
  - 劣势：内存占用高，数据量受限于内存大小
  - 性能：最优延迟

**生产推荐**: 
- **数据量 < 500万帧**: 使用HNSW（`false`）
- **数据量 ≥ 500万帧**: 使用DiskANN（`true`）

**注意**: 切换索引类型需要**重建索引**（删除collection重新创建）

---

### 2. VISUAL_ANN_TOP_K

**含义**: ANN召回数量 - 每个子查询从Milvus召回的候选帧数

**作用**:
- 决定从全量帧中快速筛选出多少"可能相关"的候选
- 这些候选会进入后续的精确评分和聚合阶段
- 越大越准确，但网络传输和计算开销越大

**取值范围建议**:

| 场景 | 推荐值 | 说明 |
|------|--------|------|
| **快速检索** | 300 | 优先速度，适合实时交互场景 |
| **标准检索** | 500 | 平衡速度和准确性（**默认值**） |
| **高精度检索** | 800-1000 | 优先准确性，适合离线分析 |
| **极致精度** | 1500-2000 | 接近全量效果，性能损失较大 |

**调优原则**:
- 如果发现召回率低（相关内容漏检），**增大** top_k
- 如果延迟过高，**减小** top_k
- 通常 `top_k = 2-5倍 × 最终返回数量` 是个好起点
  - 例如：最终返回20个结果 → top_k = 300-500

**典型配置**:
```bash
# 实时应用（延迟敏感）
VISUAL_ANN_TOP_K=300

# 标准应用（平衡）
VISUAL_ANN_TOP_K=500

# 分析应用（准确性优先）
VISUAL_ANN_TOP_K=1000
```

---

### 3. VISUAL_SAMPLE_SIZE

**含义**: 分布估算采样数 - 用于计算全局z-score分布的样本帧数

**作用**:
- 从视频的全量帧中**系统采样**一定数量的帧
- 计算这些样本帧与查询的相似度分布（median, MAD）
- 用这个分布对ANN召回的候选帧进行z-score归一化
- **保留语义**: 高z-score = 统计显著性高 = "strong"决策

**为什么需要采样分布**:
- ANN只召回"可能相关"的帧，分布是偏的（都是高分）
- 需要全局分布作为基准，才能判断某个分数是否"异常高"
- 直接拉取全量帧太慢（原问题所在），所以用采样估算

**取值范围建议**:

| 场景 | 推荐值 | 说明 |
|------|--------|------|
| **短视频** (< 5分钟) | 200-300 | 全量帧少，采样比例可以高 |
| **中等视频** (5-30分钟) | 500 | 标准配置（**默认值**） |
| **长视频** (30分钟-2小时) | 800-1000 | 需要更多样本才能准确估算分布 |
| **超长视频** (> 2小时) | 1000-1500 | 分布复杂度高，增加采样 |

**调优原则**:
- 如果发现z-score不稳定（同样内容不同查询差异大），**增大** sample_size
- 如果延迟过高且分布估算稳定，可以**减小** sample_size
- 通常 `sample_size = sqrt(总帧数)` 是统计学上合理的起点
  - 例如：1小时视频 ≈ 18万帧 → sqrt(180000) ≈ 424 → 推荐500

**典型配置**:
```bash
# 短视频场景（< 10分钟）
VISUAL_SAMPLE_SIZE=300

# 标准场景（10-60分钟）
VISUAL_SAMPLE_SIZE=500

# 长视频场景（> 1小时）
VISUAL_SAMPLE_SIZE=1000
```

**重要**: sample_size和top_k应该**相近**但不需要相等
- 如果 sample_size << top_k: 分布估算不准，z-score偏差大
- 如果 sample_size >> top_k: 浪费采样开销，意义不大
- **推荐**: `0.6 × top_k ≤ sample_size ≤ 1.5 × top_k`

---

### 4. VISUAL_SAMPLE_STRATEGY

**含义**: 采样策略

- `systematic` - **系统采样**（**推荐，默认值**）
  - 每N帧取1帧，带随机偏移避免周期性偏差
  - 覆盖视频时间轴均匀，代表性好
  - 计算效率高（Milvus表达式简单）

- `random` - 随机采样
  - 完全随机选择帧
  - 理论上无偏，但实现复杂且效率低
  - **不推荐**（已废弃）

- `stratified` - 分层采样
  - 按segment分层再随机
  - 理论上更均匀，但实现复杂
  - **不推荐**（命名历史遗留，实际未实现）

**生产推荐**: 保持 `systematic`，无需修改

## 参数组合推荐

### 配置模板1: 实时交互应用

**场景**: 前端实时搜索，延迟 < 500ms

```bash
VISUAL_USE_DISKANN=false           # 使用HNSW（最快）
VISUAL_ANN_TOP_K=300               # 快速召回
VISUAL_SAMPLE_SIZE=300             # 快速估算
VISUAL_SAMPLE_STRATEGY=systematic
```

**适用数据量**: < 200万帧

### 配置模板2: 标准生产应用（当前配置）

**场景**: 平衡速度和准确性，延迟 < 1秒

```bash
VISUAL_USE_DISKANN=true            # 支持大规模数据
VISUAL_ANN_TOP_K=500               # 标准召回
VISUAL_SAMPLE_SIZE=500             # 标准估算
VISUAL_SAMPLE_STRATEGY=systematic
```

**适用数据量**: 500万 - 5000万帧

**场景**: 内容审核、质量分析，延迟 < 3秒可接受

VISUAL_ANN_TOP_K=1000              # 高召回

**适用数据量**: 任意规模

## 性能影响分析

### 延迟组成（假设：100万帧视频，3个子查询）

| 阶段 | top_k=300 | top_k=500 | top_k=1000 |
|------|-----------|-----------|------------|
| **ANN召回** | ~50ms | ~80ms | ~150ms |
| **采样查询** (sample_size=500) | ~30ms | ~30ms | ~30ms |
| **评分计算** | ~20ms | ~30ms | ~50ms |
| **聚合决策** | ~5ms | ~5ms | ~5ms |
| **总延迟** | **~105ms** | **~145ms** | **~235ms** |

### 网络传输（假设：每帧元数据 ~200 bytes）

| top_k | 3个子查询传输量 | sample_size=500传输量 | 总传输 |
|-------|----------------|---------------------|--------|
| 300 | ~180 KB | ~100 KB | **~280 KB** |
| 500 | ~300 KB | ~100 KB | **~400 KB** |
| 1000 | ~600 KB | ~100 KB | **~700 KB** |

相比旧版全量query（83MB），优化后传输量降低 **99.5%+**

## 监控和调优

### 关键指标

1. **P50/P95延迟**: 
   - 目标: P50 < 500ms, P95 < 1000ms
   - 如果超标: 减小top_k和sample_size

2. **Top-10 Jaccard相似度**:
   - 目标: > 0.85（相比全量query）
   - 如果低于0.85: 增大top_k

3. **Z-score稳定性**:
   - 同样查询多次运行，z-score波动 < 10%
   - 如果波动大: 增大sample_size

4. **内存/磁盘占用**:
   - HNSW: 监控内存不超过80%
   - DiskANN: 监控磁盘I/O不成为瓶颈

### 调优流程

```bash
# 1. 基线测试（当前配置）
python backend/scripts/test_visual_ann.py

# 2. 调整参数（修改.env.0829）
VISUAL_ANN_TOP_K=800
VISUAL_SAMPLE_SIZE=800

# 3. 重启验证
docker restart momentseek-0829-platform

# 4. 对比测试
python backend/scripts/test_visual_ann.py

# 5. 如果Jaccard提升 > 5% 且延迟增加 < 30%，采纳新配置
```

## 常见问题

### Q1: 为什么top_k和sample_size都是500？

A: 这是经验值的巧合，但有合理性：
- top_k=500: 对于返回20个结果，25倍召回率足够
- sample_size=500: 统计学上500样本可以较准确估算分布（置信区间 ~5%）
- 两者相近使得计算开销平衡

### Q2: 能否动态调整参数？

A: 目前不支持运行时动态调整，但可以：
- 修改.env.0829
- 重启容器（热重载不会更新环境变量）
- 未来可以考虑实现基于视频时长的自适应调整

### Q3: DiskANN切换到HNSW需要重建索引吗？

A: 是的，索引类型不同，必须删除collection重新创建。

### Q4: 参数设置错误会有什么后果？

A: 不会崩溃，但可能：
- top_k过小: 召回率低，漏检
- top_k过大: 延迟高，资源浪费
- sample_size过小: z-score不稳定，决策不可靠
- sample_size过大: 延迟增加，但收益递减
